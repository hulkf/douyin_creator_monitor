# 达人基础信息表 —— 字段归属与写入规则（权威规范）

> 本文件是字段归属的**唯一权威来源**，与代码 `scripts/creator_table_fields.py` 保持一致。
> 任何脚本回写飞书前都必须按本规范做完整性/正确性校验（不写少、不写漏、不写错）。

## 四个写入方

| 阶段 | 触发点 | 负责脚本 |
|---|---|---|
| **① 接入期** | 往表里贴主页链接、系统自动接入 | `check_and_onboard_new_creators.py --apply` |
| **② 采集期** | 每天定时刷主页资料 | `collect_douyin_creator_profile.py` → `--sync-profiles` |
| **③ 备份期** | 把转写文案备份到三个地方 | `backup_transcripts_to_ima.py` / `backup_transcripts_to_kuake.py` / `export_transcript_to_obsidian.py` |
| **④ 手动** | 用户自己填 | 飞书界面 |

另外：`创建时间` 是飞书系统自动，不由脚本写；`认证信息` 流水线不抓，长期为空（正常）。

## 校验如何落地（代码侧）

`sync_creator_backup_mapping_to_feishu.py` 之外，三个写入脚本在回写飞书前均调用 `creator_table_fields` 的校验器：

- 接入期：`validate_onboard_patch(patch, sec_uid)` —— 必填缺失 → 告警列出（抖音UID 已不再由接入期写入，故此处不再涉及）。
- 采集期：`validate_profile_patch(patch)` —— 必填缺失会告警；类型不符、账号ID 疑似被填成 SecUID，以及抖音UID 等于 SecUID 或非纯数字时，会在写回前移除该字段并告警，从而保留飞书历史正确值。
- 备份期：`validate_backup_patch(patch)` —— 同一平台组字段不齐 → 告警列出缺哪些。

校验器**只告警、不阻断写入**（且模块缺失时降级为无操作），保证主流程永不因校验逻辑而中断。
